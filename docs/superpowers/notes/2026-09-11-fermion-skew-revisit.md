# skew boundary はフェルミオンで使える — 2026-08-20 の「skew で符号が壊れる」判定の取り消し

日付: 2026-09-11。binary: HEAD 03cd7cd6(out-gcc Debug、g++-16、MPI off)。
作業ツリーは無変更。ガード解除は `bin/tenes`(load_toml.cpp の使い捨てコピーを
コンパイルして HEAD のアーカイブとリンクした実験専用 binary)と `tool_snapshot/`

## 問いと結論

問い: `skew != 0` の単位胞でフェルミオン符号機構は正しいか。
結論: **正しい。** skew セルと、その展開(skew 0 の等価セル)で同一状態から
simple update を回すと最終テンソル・λ が **ビット単位で一致** し、CTM 測定の差は
有限 χ の打ち切り誤差で χ を上げると縮む。skew に依存するコードはフェルミオン
機構に存在しない。

## 2026-08-20 の判定(work/fermion/skew-validation/FINDINGS.md)が失効した理由

1. **fold バグ修正前の binary だった。** kDoubledJointMask の 2 ペア欠落
   (3bef24a4 で修正)は真の 2D 形状で効き、FreeFermion golden の D=2 エネルギーは
   -0.73284 → -0.72345 に変わっている。8 月の C(skew 0)・D(skew 1)は両方その
   バグを含む。
2. **skew と幅 1 セルを分離していなかった。** 比較対象 D は L_sub=[2,1] skew 1。
   幅 1 セルには skew と無関係な問題がある(後述)。
3. **ansatz の制限を符号の誤りと読んだ。** [2,1] skew 1 は T(x,y) = T(x+1,y+1) で、
   [2,2] skew 0 の計算を T0 = T3、T1 = T2 に制限したものと厳密に一致する(実験 2 の
   ビット一致)。この cell は副格子を保つので市松 CDW(D=2 の [2,2] 解のサイト密度
   0.680/0.320/0.320/0.680)も表現できるが、SU は対称な部分空間から出られず、HEAD でも
   自由フェルミオンは -0.63〜-0.66 に留まる([2,2] skew 0 は -0.7234)。同じことは
   ボゾンの XY 強磁性でも起きる(実験 1)。8 月の Heisenberg AF 対照はたまたまこの制限に
   掛からない状態だったので「対照は平坦」に見えた。
   (訂正 2026-09-11: 初版は「skew セルは副格子を入れ替えるため市松を表現できない」と
   書いたが、それが成り立つのは [2,2] skew 1 のように T(x,y) = T(x+1,y+2) で副格子を
   入れ替える cell だけで、8 月に比較した [2,1] skew 1 には当てはまらない。レビューで指摘。)

## 理論とコード監査

符号機構は (site, leg) 単位の parity 台帳と graded 縮約で閉じており、格子情報は
`lattice.neighbor()` / `lattice.other()` 経由でしか入らない。skew はこの neighbor map
だけを変える(SquareLattice.cpp:95-98)。監査結果:

| 経路 | 格子アクセス | skew 依存 |
|---|---|---|
| simple_update.cpp | `lattice.neighbor(source, source_leg)`、向きは source_leg のみ | なし |
| full_update.cpp | `lattice.neighbor`、`validate_neighbor_consistency(finfo, lattice)`。高速 FU の環境更新 `update_CTM_fast_fermion` は `source % LX` / `source / LX` で列・行を選び、移動は `index()` と `LY_noskew` で skew を解決する(ボゾン分岐と同じ表。ボゾン側は Honeycomb_skew がカバー、フェルミオン側の列・行選択を直接比べるテストは無い) | なし |
| twosite_obs.cpp | 窓を `lattice.other(source, dcol, drow)` で構築、上下左右は (dx,dy) の符号で決定 | なし |
| measure.cpp / reduced*.hpp | サイト単位 fold、格子を知らない | なし |
| density CTM | ボゾン共通。FT_Kitaev(L_sub=[2,1] skew 1)が ctest で常時カバー | なし |
| saveload | skew を書き出し・照合 | なし |
| 手計算の隣接 `(iy+1)%LY` 等 | transfer_matrix.cpp のみ(skew を明示処理、fermion では無効化済) | — |

## 実験 2: 展開厳密テスト(unfold/、unfold.py)— これが判定根拠

skew セル [LX,LY] skew s は、[LX, LY·m](m = lcm(LX,s)/s)skew 0 のセルに
展開できる: 展開サイト (x,y) ← skew サイト ((x − s·⌊y/LY⌋) mod LX, y mod LY)。

手順:
1. skew セルで num_step=0 を回し初期乱数状態を tensor_save
2. チェックポイントを展開(T/λ/環境プレースホルダ/params.dat/fermion.dat をサイト写像で複製)
3. 展開セルの input.toml は evolution リストを **像ペア順** に並べる
   (skew ボンド b の m 個の像を連続適用)。像同士は互いに素なテンソル・λ しか
   触らないので、各ペア適用後の展開状態は skew 状態の展開と厳密に一致する
4. 両セルで同じ step 数の SU → CTM 測定 → tensor_save し、最終テンソルを比較

skew セルは実験 binary、展開セルは **無改造の HEAD binary**(skew 0・両辺 ≥ 2 なので
ガードを通る)。

- SU: 全ケース(seed 11/23/5/7 の [2,1] s1 を含む)でビット一致。**skew セルの simple update は
  展開セルと同一の状態を作る。**
- [2,1] s1 の SU 由来状態は 4 seed 中 3 つで CTM が 1000 回でも収束せず、測定差は収束の
  悪さに比例する(seed 7 の 4e-4 収束で 6e-8、seed 5 の 1.4 で 4e-4)。展開セルでも同様に
  未収束なので状態の性質。測定経路の検証は実験 3(fold テスト、1e-13)で別途行った。
- 測定: 差は CTM の収束条件を締めても変わらず、χ を 8→32 にすると 80 倍縮む。
  有限 χ の CTMRG 打ち切りがセル形状に依存する既知の効果で、符号の誤りではない
  (符号誤りなら O(1) の差が出る。8 月は 20%)。
- サイト別・ボンド別の比較ではノルム行(op index -1)を除外している。ノルムは環境の
  規格化に依存する非物理量で、セル間で 2e-3 違うが観測量には影響しない。

## 実験 3: [2,1] skew 1(tenes_simple の L=2, W=1)の測定経路 — fold テスト(fold/、fold_measure.py)

[2,1] skew 1 は SU 由来の状態だと skew セル・展開セルの両方で CTM が収束しないため、
実験 2 では測定経路を検証できなかった。そこで CTM が収束する状態を別に用意した:
収束済み [2,2] skew 0 解(seed 11、E=-0.7234481)の T0, T1 をそのまま [2,1] skew 1 の
2 テンソルとし(測定は bare Tn しか使わないので λ の整合は不要。parity 台帳は 4 ボンド
とも [0 1] で整合)、同じ状態を [2,2] skew 0 に展開した (T0, T1, T1, T0) と num_step=0 で
測定比較。skew セルは実験 binary、展開セルは HEAD binary。χ=32、ε=1e-10。

| 量 | skew [2,1] | 展開 [2,2] | 差 |
|---|---|---|---|
| Energy | -6.554599025984e-02 | -6.554599026008e-02 | 2.4e-13 |
| n | 0.5012768860165817 | 0.5012768860165822 | 4e-16 |
| nn | 0.5659430251530 | 0.5659430251532 | 1.3e-13 |
| サイト別 max / ボンド別 max | | | 3.2e-13 / 4.9e-13 |

両セルとも CTM 収束。**[2,1] skew 1 は SU(実験 2、ビット一致)と測定(本実験、1e-13)の
両方で展開セルと一致する。** (T0,T1,T1,T0) は元解のゲージが T2,T3 と合わないため
エネルギーは悪いが、等価性テストの状態としては正当。

full update は evolution.full に 1 ゲートだけ置いて num_full_step = 1 で回した(恒等ゲート
自動挿入は simple update のリストにしか掛からない)。展開側で像 2 のサイトは無変更を確認。
更新量は |ΔT| ~ 1 なので自明な一致ではない。高速 full update の CTM 移動は
ボゾンと共通の skew 対応コード(ctm_single.cpp の LY_noskew ループ)で、ボゾンの
Honeycomb_skew ctest([2,1] skew -1、FU 10 step)が常時カバーしている。

## 幅 1 セルについて(skew とは独立の観察)

- XY 強磁性 [2,1] s1 は SU が **積状態に単調収束** する(E: -0.084 → -0.162(20 step)
  → -0.492(100)→ -0.49999878(300)→ -0.5000000(1000))。展開した [2,2] s0 でも
  同一初期状態からビット一致で同じ積状態に落ちるので、セル実装のバグではなく
  「市松対称な初期状態からの SU の力学的な罠」。Heisenberg AF は 8 月同様 7 桁一致。
- フェルミオン [2,1] s1 / [2,1] s0 の SU 由来状態は CTM が未収束(rdm_dist 0.12〜0.65)。
  展開セルでも未収束なので状態自体の性質。測定経路そのものは実験 3 で 1e-13 一致。
- [N,1] skew 0(自己ボンド)は SU が Tn を 2 回書いて後勝ちになる TeNeS 共通の挙動で、
  展開しても像が同じテンソルを共有するため厳密テストの射程外。

## 推奨

1. **skew != 0 のガードは 3 層(tenes_simple / tenes_std / load_toml.cpp)とも解除できる。**
   根拠は上表。ただし解除は回帰テストと同時に行う。
2. **回帰テスト**: 展開恒等性を C++ 側で固定する。[2,2] skew 1 と [2,4] skew 0 に
   同一テンソルを置き、像ペア順の evolution で k step 回して Tn/λ を厳密一致
   (1e-14)、CTM 測定を 1e-6(χ=8)で一致させる。既存の
   `fermion twosite measurement is translation invariant across wraps` の
   iTPSTestAccessor 流儀で書ける。python 側は tenes_simple の `W=1`(skew 1)を
   フェルミオンで受理するテストを追加。
3. **幅 1 セルのガード(L_sub ≥ 2)は当面据え置き。** skew の問題ではないが、
   SU の罠と CTM 未収束が実測されており、解除しても得るものが無い。skew != 0 の
   幅 1 セルはボゾンと同じ扱いにする選択肢もある(展開等価性は証明済み)。
   → **不採用(2026-09-11)。** 実験 3 で測定経路も 1e-13 で一致したのを受け、ユーザー判断で
   ボゾンと同じ扱いにした。拒否するのは自己隣接セル(LX = 1、または LY = 1 で skew が LX の
   倍数)だけ。実用上の癖は残る: レビューでの実測では、tenes_simple の W = 1 を sample 08
   の設定(D=2、chi=8、iteration_max=100)で回すと SU は CTM 未収束の警告付きで E = -0.573
   (W = 2 は -0.684)、full update は 1 step 目で「CTM environment is not parity clean」で
   止まり、iteration_max = 1000 なら完走する。NEWS に iteration_max を上げる旨を書いた。
4. docs の制限一覧(load_toml.hpp のコメント、Sphinx)から skew の項を落とす。
