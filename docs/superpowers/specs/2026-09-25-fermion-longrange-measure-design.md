# fermion モードの長距離二サイト物理量と相関関数 — 設計書

- 日付: 2026-09-25
- ブランチ: `fermion-longrange`(develop 06780eac から)
- 実験・台帳: `work/fermion-longrange/<topic>/`

## 1. 目的と範囲

fermion モード(Z2 グレード iPEPS)で、現在は入力時に拒否している次の測定を使えるようにする。

**やること**

1. 最近接以外の二サイト物理量。任意の (dx, dy) を、ボソンと同じく窓 4×4 まで(|dx| ≤ 3 かつ |dy| ≤ 3)扱う。CTM 環境。
2. 相関関数(`[correlation]`、`r_max > 0`)。⟨c†_0 c_r⟩ のような奇×奇の組と、⟨n_0 n_r⟩ のような偶×偶の組の両方を扱う。CTM 環境。
3. 上の 2 項目の前提として、パリティ奇の一サイト演算子(c, c† など)の**定義**を許す。一サイト測定の値は厳密に 0 とする。
4. ops 形式の二サイト物理量(`ops = [i, j]`)。
5. `tenes_simple` の fermion モデルに c, c† の一サイト演算子を追加し、`[correlation]` を受理する。
6. 後続フェーズとして、MF 環境(`meanfield_env = true`)での 1・2 を扱う(§6)。

**やらないこと**

- multisite 物理量、相関長(転送行列の固有値)。どちらも従来どおり拒否・無効化する。
- 最近接以外の Hamiltonian 項(時間発展ゲート側)。`tenes_std` の拒否を維持する。
- 窓 4×4 を超える二サイト物理量。
- 有限温度・実時間。fermion モード自体がまだ対象外。

## 2. 現状

- CTM 環境は、各サイトの bra×ket を fold した rank-6 の reduced テンソル
  `([l lb], [t tb], [r rb], [b bb], s_ket, s_bra)` から、ボソンの density 用ビルダー
  `Calc_CTM_Environment_density` で作っている(`src/iTPS/iTPS.cpp` の `update_CTM()`)。
  fold の規約は `kDoubledJointMask`(`src/fermion/reduced.hpp`)。恒等ネットワークについては、
  任意の平面パッチで Fock oracle と一致することを検証済み(`docs/superpowers/notes/2026-08-28-fermion-folding-methodology.md`)。
- density カーネルには、長距離に必要な縮約がすでに揃っている。nrow×ncol 窓の
  `Contract_density_CTM`(`core/contract_density_ctm/ctm_1x1.cpp`〜`ctm_4x4.cpp`)と、相関関数の
  `StartCorrelation/Transfer/FinishCorrelation_density_CTM` である。
- 最近接の二サイト測定は bundled-k 方式で行っている(`build_reduced_pair_halves_from_factors`)。
  graded SVD `O = Σ_k u_k ⊗ vt_k` の k 脚を、両サイトの共有ボンド脚に隣接融合する。
  このとき片側に交差符号 `(-1)^{p_bond·p_k}` を掛ける。融合した 1 本の脚として縮約すると、
  graded 縮約での 2 本の脚の交換符号が抜けるので、それを補う符号である。
- 拒否箇所: `load_toml.cpp` の `validate_fermion_constraints`(距離 2 以上、ops 形式、奇の一サイト演算子、
  `r_max > 0`)、`measure.cpp` の `validate_fermion_ctm_measurement`、
  `tenes_simple.py` の `_check_fermion_scope`(`[correlation]`)。

## 3. 方式: 符号の紐を仮想ボンドに沿ってリレーする

### 3.1 考え方

二サイト演算子を graded SVD でチャネル k に分ける。各チャネルの因子 u_k, vt_k はパリティ p_k が確定している。
チャネル k を固定すると、k 脚は**次元 1・パリティ p_k の補助脚 κ** になる。
奇チャネルでは κ が「紐」の役割を持つ。紐を source から target まで**正方格子の仮想ボンドに沿って**リレーすると、
ネットワークのすべてのテンソルが再びパリティ偶になる。途中のサイトでは、入口と出口の向きから紐を融合する脚が機械的に決まる。
符号は graded transpose と fold の既存機構から自動的に出てくるので、手で導く符号表は作らない。

κ は次元 1 なので、ボンドに融合しても次元は変わらない。変わるのはそのボンドのパリティ表(p_k が奇なら反転)だけである。
fold 後のテンソルは既存と同じ形の rank-6 になり、density カーネルにそのまま渡せる。
チャネルの和はループの外で取る。これはボソンの長距離経路(`twosite_obs.cpp` の SVD チャネルループ)と同じ形である。

偶チャネルでは κ は偶で、符号はすべて自明に +1 になる。偶と奇を場合分けせず、同じコードで扱う。

### 3.2 経路

窓の中で source から target への経路を 1 本選ぶ。本番の既定は **x 先行**(source の行を target の列まで進み、そこから target の行まで進む)とする。
builder は **y 先行**も選べるようにする。経路非依存性の検査(§3.5)に使うためである。
経路の各段は、隣接する 2 サイトの共有ボンド 1 本に対応する。

### 3.3 窓の各サイトの ket 層

| サイトの役割 | ket 層のテンソル | κ の融合先 |
|---|---|---|
| source | `tensordot(Tn_s, u_k)`。u_k は (in, out, κ) | 出口ボンド脚 |
| target | `tensordot(Tn_t, vt_k)`。vt_k は (κ, in, out) | 入口ボンド脚 |
| 経路上の途中サイト | `Tn_m ⊗ S`。S は κ_in, κ_out(どちらもパリティ p_k)を持つ値 1 の偶テンソル | κ_in を入口、κ_out を出口 |
| 経路外 | `Tn`(従来どおり) | なし |

- κ を融合先の脚の隣へ移すのは、`ftensor` の graded transpose で行う。融合の順序と交差符号は bundled-k と同じ規約に揃える。
  すなわち、ボンドの**経路上流側**(source 寄り)のサイトで融合脚に `(-1)^{p_bond·p_k}` を掛ける。
  この規約の正しさは §3.5 の検査で確かめる。bundled-k 側の実装は変更しない。
- bra 層はどのサイトでも素の `Tn` のままとする(演算子は ket 側にだけ作用する)。
- fold は `detail::doubled_pipeline(bra = Tn, ket = 上表)` で行い、物理脚を開いた rank-6 を得る。
  カーネルには恒等の一サイト演算子を渡し、物理脚をトレースさせる。
  端点の演算子因子を fold の前に ket へ吸収するのは、fold の前提(各層がパリティ偶)を守るためである。
- 最近接 (|dx| + |dy| = 1) では、この構成をチャネルについて足し合わせたものが bundled-k に一致するはずである。

### 3.4 縮約

- 二サイト物理量: チャネルごとに窓テンソル一式を作り、`Contract_density_CTM` で縮約して `s_k` 重みで足す。
  ノルムは経路外と同じ reduced テンソルだけの窓で計算する。値とノルムを同じ環境テンソルで計算するので、
  fermion 環境の窓ごとの全体位相(`2026-09-05-fermion-ctm-phase-design.md`)は比の中で打ち消し合う。
- 相関関数: 左端を source、右端(垂直なら上端)を target とする直線の経路になる。
  `StartCorrelation_density_CTM` に source のテンソルを渡す。
  `Transfer_density_CTM` には途中サイトの紐付きテンソルを渡す(ボソン版で `Tn[right_index]` を渡している位置)。
  `FinishCorrelation_density_CTM` には target のテンソルを渡す。
  垂直方向は、物理的な向き(入口 = 下、出口 = 上)で紐付きテンソルを作り、そのあとボソン版と同じ脚の回転(`Axes(3,0,1,2,4,5)`)を掛ける。
  ノルム側の鎖は従来の reduced テンソルで作る。

### 3.5 前提の検証と中止条件(タスク T1 のゲート)

この方式は「graded 機構を機械的に適用すれば、どの経路で紐を引いても同じ値になる」ことを前提にしている。
2026-08 の fold バグは 1×N と 2×2 で正しく見え、非自明な脚が 3 本以上のサイトで初めて破れた。
同じ種類の見落としを避けるため、T1 で次の 3 点を**すべて**満たしてから T2 以降に進む。

1. **厳密照合**: 外周の脚を次元 1 に閉じた有限パッチで、ランダムなパリティ偶テンソルを使う。
   fold した窓の厳密縮約が、単層 graded 縮約による真値と一致すること。
   真値は `work/fermion/ctm-fold-check/fold_check3.cpp` と同じ構成で作る。
   さらに少数のケースを `test/fermion/fock_oracle.py` と照合する。
   ケースには、直進 (2,0)・(3,0)・(0,2)・(-2,0)、4 方向すべての曲がり角 (1,1)・(1,-1)・(-1,1)・(-1,-1)・(2,1)、
   途中サイトに非自明な脚が 3 本以上ある配置(2×3・3×3 パッチの内部を通る経路)を含める。
   d = 2(spinless)と d = 4(Hubbard)の両方で行う。
2. **経路非依存性**: 同じケースを x 先行と y 先行で計算し、一致すること。
3. **最近接の一致**: |dx| + |dy| = 1 で、既存の bundled-k(`build_reduced_pair_halves`)と丸め誤差の範囲で一致すること。

経路によって値が変わる、または真値と合わない場合は、その時点で実装を止める。原因を特定し、設計書を改訂してから再開する。
builder を部分的に「測定で合わせる」ことはしない。これは旧 `apply_fused_leg_gauge` の教訓による。

## 4. 演算子と出力の定義

### 4.1 一サイト演算子のパリティ

- 一サイト演算子は、すべての非零要素が偶(パリティを保つ)か、すべてが奇(パリティを 1 だけ変える)かのどちらかでなければならない。
  偶奇が混在するものは入力時に拒否する。
- 奇の一サイト演算子は、一サイト測定(`onesite_obs.dat`)で厳密に 0 を出力する。
  縮約は行わない。状態がパリティ偶なので期待値は恒等的に 0 になる。
- 奇の一サイト演算子を一サイトゲート(時間発展)に使うことは、従来どおり拒否する。

### 4.2 二つの一サイト演算子の積

相関関数と ops 形式の二サイト物理量は、どちらも「source の演算子 A と target の演算子 B の積 A_s B_t」を測る。
これを、明示形式の二サイト物理量と同じ基底規約(順序付き Fock 基底 |n_s n_t⟩ = (c†_s)^{n_s} (c†_t)^{n_t} |0⟩)の 4 脚行列に直してから、§3 の機構に渡す。

    ⟨o_s o_t| A_s B_t |i_s i_t⟩ = (-1)^{p_B · p(i_s)} A[o_s, i_s] B[o_t, i_t]

こうすると、r = 1 の相関関数と、同じ演算子の最近接二サイト測定が同じ経路を通る。
符号因子の正しさは T2 の単体テストで Fock oracle と照合して確かめる(⟨c†_s c_t⟩ と ⟨c_t c†_s⟩ = −⟨c†_s c_t⟩ を含める)。

- p_A ≠ p_B の組は、期待値が恒等的に 0 になる。縮約せずに 0 を出力する。
- 出力値は ⟨A_s B_t⟩(A が左)とする。`correlation.dat` の列構成はボソンと同じにする。

### 4.3 二サイト演算子のパリティ

演算子全体がパリティ偶である(`parity-odd two-site operators` のガード)という制約は維持する。
graded SVD のチャネルは偶⊗偶か奇⊗奇のどちらかになる。

## 5. 入力ガードとツール

### 5.1 C++

- `validate_fermion_constraints`:
  - 距離 2 以上の二サイト物理量を受理する。|dx| > 3 または |dy| > 3 は、fermion では入力エラーにする
    (ボソンは警告を出して読み飛ばすが、fermion モードは未対応の入力を読み込み時に拒否する方針なので)。
  - ops 形式を受理する。ただし §4.1 のパリティ確定を満たすこと。
  - `r_max > 0` を受理する。
  - 奇の一サイト演算子の拒否を、「偶奇混在の拒否」に置き換える。
  - multisite の拒否は維持する。
  - 後続フェーズ(§6)が入るまでは、`meanfield_env = true` で最近接以外の二サイト物理量、ops 形式、`r_max > 0` を指定した場合も拒否する。
- `validate_fermion_ctm_measurement`: 上と同じ条件に揃える(二重ガードとして残す)。

### 5.2 `tenes_simple`

- spinless には `cdag`, `c` を、Hubbard には `cdag_up`, `c_up`, `cdag_dn`, `c_dn` を、既存の一サイト演算子の**後ろに**追加する。
  既存の演算子番号は変わらない。
- fermion モデルで `[correlation]` を受理する。`operators` を省略した場合の既定値は、
  偶の一サイト演算子について [g, g] の組、奇の演算子について [cdag_σ, c_σ] の組とする。
- `[correlation_length]` の拒否は維持する。
- 一サイト演算子を追加すると、既存の fermion のテスト・サンプルの `onesite_obs.dat` に行が増える。
  該当する golden ファイルは同じタスク内で**意図的に**再生成する。既存の行の値が変わらないことを差分で確認する。

## 6. 後続フェーズ: MF 環境

MF 環境は「窓の外側を λ で閉じる」近似である。ボソンでは `Contract_iTPS_MF` を使っている。fermion では、次のように CTM 経路を丸ごと流用する。

- 外周の脚を λ で dress した境界テンソルのコピー(ボソンの MF 窓と同じ)を fold し、
  外周の融合脚 `[x xb]` を δ_{x,xb} で閉じる。実装上は、χ = 1 の合成環境(C = 1、eT = δ)を作り、§3.4 と同じ density カーネルに渡す。
- **ゲート**: 最近接で、この構成が既存の `contract_pair_MF`(単層 graded 縮約)と丸め誤差の範囲で一致すること。
  一致しなければ、δ 閉包に符号(supertrace)が要るということなので、設計を改訂する。

## 7. テスト方針

著者分離(ユーザー指示)に従う。テスト作成者には振る舞い契約書(散文)だけを渡す。
計画者のテストコードは渡さない。実装担当(Codex)はテストを変更しない。

- **単体(C++, doctest)**
  - T1: §3.5 の 3 条件。変異防衛として、κ の graded transpose を素の transpose に替える、
    交差符号を落とす、の各変異で必ず赤くなることを確認する。
  - T2: 窓測定の値が、ランダムな環境テンソルの下でも §3.5 と同じ構成の値と一致すること(カーネルの配線の検査)。§4.2 の符号の Fock 照合。ガード。
  - T3: 相関関数の r = 1..3 が、同じ環境テンソルの下で同じ演算子の窓測定と一致すること。
    転送と窓縮約は同じネットワークなので、環境がランダムでも一致する。水平と垂直の両方で行う。
- **E2E(Python, ctest)**
  - 自由フェルミオン(spinless)で、(2,0)・(1,1)・(2,1)・(3,0) の ⟨c†_0 c_r⟩ と、`r_max` までの相関関数を、
    運動量積分による解析値と比べる。許容誤差は、相殺しない量に錨を置いて決める(`2026-09-05-fermion-test-tolerance-contract.md` の教訓)。
    golden ファイルとの比較も行う。
  - Hubbard の小さい D で、⟨c†_{↑,0} c_{↑,r}⟩ = ⟨c†_{↓,0} c_{↓,r}⟩(スピン対称性)と、偶演算子 SzSz の相関関数が有限であることを見る。
- MPI: 窓と相関関数のカーネルは分散テンソルのまま動く。n = 2 の ctest 登録を 1 件入れる。

## 9. リスク

- **符号規約の見落とし**: §3.5 のケース選定で、非自明な脚が 3 本以上あるサイトと 4 方向の曲がり角を必ず踏む。
- **コスト**: d = 4 の二サイト演算子はチャネルが最大 16 本になる。4×4 窓 × 16 チャネルは、ボソンの同じ測定と同程度のコストになる。
  チャネルの束ね(κ の次元を 1 より大きくする)は、必要が示されるまで行わない。
- **golden の再生成**: 一サイト演算子の追加で既存の出力に行が増える。既存の行の値が変わらないことを差分で機械的に確認する。
