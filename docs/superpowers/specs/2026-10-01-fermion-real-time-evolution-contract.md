## 1. 共通の前提

- 「fermion モード」は `[parameter.general] fermion = true` と、各サイトの `[[tensor.unitcell]] parity` で有効になる。
- 実時間発展は `[parameter.general] mode = "time"`。`tenes_std` が `tau` に `1j` を掛けたゲート exp(−i·tau·H) を作る。出力は `TE_` で始まるファイル(`TE_onesite_obs.dat` など)で、各行の先頭列が時刻である。時刻 0(発展前)にも測定する。
- 以下の Hubbard 模型の 1 サイト基底は `tenes_simple` の規約に従う:index 0 = |0⟩、1 と 2 = 1 電子状態、3 = |↑↓⟩(doublon)、`parity = [0, 1, 1, 0]`。1 サイト演算子 `n`(密度)は対角 (0, 1, 1, 2)。
- `tenes_simple` の Hubbard で `initial = "cdw"` を使うと、副格子 0(座標の和が偶数のサイト)が |0⟩、副格子 1 が |↑↓⟩ になる。
- 2 サイトセル:`L_sub = [2, 1]`、`skew = 1`。サイト 0 が (0,0)、サイト 1 が (1,0)。このセルでは、サイト 0 の右と下、サイト 1 の左と上が互いにつながり(右上がりの階段)、サイト 0 の上と左、サイト 1 の下と右も互いにつながる(右下がりの階段)。仮想脚の順は (左, 上, 右, 下)。

## 2. 実時間発展の配線(ボソン等価性)

**振る舞い**:グレーディングが自明(全サイトの `parity` がすべて 0)な fermion モードの実時間発展は、同じ入力のボゾン版と同じ結果を出す。

- 基準入力は `test/data/TE_TFI.toml`。fermion が拒否する設定(マルチサイト観測量、相関長)は両方の入力から外す。違いは `fermion = true` と `parity` の 2 か所だけにし、テストの中でそれを確かめる(既存の `test/fermion/boson_equivalence_full.py.in` と同じ作法)。
- SU 版:`TE_TFI` の SU 設定のまま。FU 版:SU のステップ数を 0 にして同じ時間刻みの FU を走らせる(ステップ数は 30 秒に収まるように減らしてよい)。
- 比較する出力:`TE_onesite_obs.dat`、`TE_twosite_obs.dat`、`TE_correlation.dat`(`[correlation]` があるので fermion 版も必ず出力する。欠けていたら失敗)、`TE_density.dat`。全行・全列(時刻、実部、虚部)が許容誤差内で一致する。
- 実装前は fermion 版が入力時に `non-ground-state mode` を含むエラーで止まるはずである。

## 3. 自由フェルミオンの厳密解

模型はすべて `t = 1`、`U = 0`、`mu = 0` の Hubbard、`tau = 0.01`。厳密解の導出と数値確認(40×40 周期格子の一粒子計算で 1e-15 一致)は設計書 §4 を参照。

### 3.1 鎖を埋め込んだ 1D(SU、平均場環境)

**振る舞い**:2 サイトセルに埋め込んだ 1D 鎖で、doublon から始めたサイトと空から始めたサイトの密度差 n_1(T) − n_0(T) が 2·J0(4T) に従う(J0 は第一種ベッセル関数)。

- 鎖は 4 通り:横鎖(サイト 0 の右とサイト 1 の右)、縦鎖(サイト 0 の上とサイト 1 の上)、右上がり階段(サイト 0 の右とサイト 1 の上)、右下がり階段(サイト 0 の右とサイト 1 の下)。ハミルトニアンのボンドは鎖の 2 本だけで、鎖に使わない仮想脚の次元は 1、鎖の脚は D = 8。
- 初期状態はサイト 0 が |0⟩、サイト 1 が |↑↓⟩。平均場環境(`meanfield_env = true`)、30 ステップ、T = 0.1, 0.2, 0.3 で測る。
- P0 の実測:D = 8 で T ≤ 0.3 の差は 1e-5 以内。4 通りの鎖は互いに 6 桁一致した。
- 4 通りの鎖の結果が互いに一致することも確かめる(raster 順に対する鎖の向きで結果が変わらないこと)。

### 3.2 鎖を埋め込んだ 1D(FU)

**振る舞い**:同じ右上がり階段の鎖で、FU でも 2·J0(4T) に従う。

- D = 4、CTM 環境(`meanfield_env = false`、`dimension = 16`)、20 ステップ、T = 0.1, 0.2 で測る。`fastfullupdate = true` と `false` の 2 通り。
- P0 の実測:どちらも T = 0.2 で差 5.6e-5。

### 3.3 2D 正方格子(正規経路、CTM)

**振る舞い**:`tenes_simple` → `tenes_std` → `tenes` の正規経路で作った 2D の Hubbard を `initial = "cdw"` から発展させると、n_1(T) − n_0(T) が 2·J0(4T)² に従う。

- `tenes_simple` の入力:`square lattice`、`L = 2`、`W = 1`、`virtual_dim = 3`、`noise = 0`、`mode = "time"`、`is_real = false`、CTM 環境で `dimension = 9`、10 ステップ、`measure_interval = 10`。
- T = 0.1 で比べる。P0 の実測:差 2.3e-3(2 からのずれ 0.155 に対して 1.5%)。D = 2 にすると T² の係数が半分になる(打ち切りのため)ので、この設定を変えないこと。
- 全密度 n_0 + n_1 = 2 が保たれることも確かめる。

## 4. 1 サイトゲートと時間の向き

**振る舞い**:1 サイトのハミルトニアン H = Δ(|↑↓⟩⟨0| + |0⟩⟨↑↓|)(Δ = 1)だけを持つ fermion の実時間発展は、真空のプロダクト状態から始めて
|ψ(T)⟩ = cos(ΔT)|0⟩ − i·sin(ΔT)|↑↓⟩ になる。したがって

- ⟨n⟩(T) = 2·sin²(ΔT)
- 1 サイト演算子 O = |0⟩⟨↑↓|(行列要素 ⟨0|O|↑↓⟩ = 1 だけを持つ演算子)の期待値は ⟨O⟩(T) = ⟨ψ|0⟩⟨↑↓|ψ⟩ = −i·cos(ΔT)·sin(ΔT)。
  虚部が負であることが、発展が e^{−iHT}(正しい向き)であることを示す。

- 2 サイトセル、全サイトが |0⟩、2 サイトのハミルトニアンなし、D = 2(任意)。50 ステップ、`measure_interval = 10`(T = 0.1, …, 0.5)。
- SU(平均場環境)と FU(CTM 環境)の両方。
- 1 サイトゲートは厳密な指数なので、Trotter 誤差はない。期待される差は丸め誤差の程度である。
- O の行列要素を `elements` でどう書くか(どちらの index が bra か)は、ドキュメントと `src/` の読み込み処理から確かめ、その根拠をテストのコメントに書く。この結果自体に合わせて決めてはならない。
- `tenes_std` に 1 サイトのハミルトニアンを渡す std.toml の書き方は、`tool/tenes_std.py` と既存のテストから確かめる。

## 5. load からの実時間発展

**振る舞い**

1. fermion の基底状態計算を `is_real = true` で行って `tensor_save` したテンソルは、complex の計算(実時間発展)で `tensor_load` できる。
   load した状態を時刻 0 で測った値(`TE_onesite_obs.dat` と `TE_twosite_obs.dat` の時刻 0 の行)は、保存元の基底状態計算の測定値(`onesite_obs.dat`、`twosite_obs.dat`)と一致する(虚部は 0)。そのまま実時間発展が完走する。
2. `is_real = false` で保存した場合も同じ。
3. complex で保存したテンソルを `is_real = true` の計算で `tensor_load` すると、tenes は非ゼロの終了コードで止まり、メッセージに `complex` と `is_real` の両方を含む。
4. ボゾン(fermion モードでない)でも、`is_real = true` で保存したテンソルを complex の計算で読んだ時刻 0 の測定値が、保存元と一致する。
5. 1 と 4 は、MPI が有効なビルドでは 2 ランクでも確かめる(保存も読み込みも 2 ランク)。MPI が無効なビルドでは登録しない(既存の `*_mpi2` テストの作法に合わせる)。

- 基底状態計算は短くてよい(例:Hubbard `U = 4`、`mu = 2`、2 サイトセル、`initial = "random"`、`virtual_dim = 3`、SU 300 ステップ、平均場環境)。読み込み側は別のハミルトニアン(例:`U = 0`)で、測定環境は保存元と同じにする。比較は基底状態の測定と同じ環境どうしで行う。
- ボゾンの 4 は、例えば `TE_TFI` 相当の模型で `is_real = true` の基底状態計算を短く走らせて保存し、実時間で読む。
- 実装前の期待:1 と 4 は失敗する(1 は fermion のパリティ検査が `breaks fermion parity` で止める。4 は Release では壊れた値で走り切り、Debug では mptensor の assert で abort する)。どちらの理由で落ちたかを報告に書く。2 は実装前でも、fermion の実時間が入力時に拒否されるため失敗する。3 は実装前は Debug で abort、Release では壊れた値で走るか別のエラーになる。

## 8. 実時間 SU の台帳検査(追補、2026-10-01、Task 1 レビューを受けて)

**振る舞い**:fermion モードの実時間発展(`mode = "time"`、simple update)は、各ステップで全ゲートを適用し終えた時点で、
各サイトの物理パリティ台帳が入力の `parity` に戻っていることを検査し、戻っていなければ `std::logic_error` を投げる
(メッセージは基底状態の simple update と同じ "fermion simple update invariant violated: physical ledger did not return to its original value after a gate sweep")。

正しい入力では入力時の台帳推定が同じ条件を先に保証するので、E2E では発火しない。C++ 単体テスト(`test_fermion_common.hpp` の `iTPSTestAccessor` で内部状態に触れてよい)で次を確かめる。

- A:ひとつの group の中で物理台帳を一時的に変えて戻すゲート列(長距離ボンドのゲート列)を含む実時間 SU が、例外なく完走する。
- B:ステップの終わりで台帳が入力と食い違っている状態(台帳または `phys_parity` を改ざんして作る)では、実時間 SU が上の `logic_error` を投げる。
- C:検査はゲートごとではなくステップの終わりに行われる。A が完走することがこれを示す(ゲート列の途中で検査すると A が落ちる)。

実装前(da46fa90 より前)の振る舞いでは B が赤になる。da46fa90 以降は緑になるはずである。
検出力の確認として、`time_evolution()` の検査呼び出しを消したコピーで B が赤になり、検査をゲートごとに移したコピーで A が赤になることを報告に書く。
